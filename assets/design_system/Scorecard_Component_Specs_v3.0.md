# ✨ Data Integrity Scorecard: 최종 컴포넌트 명세서 (v3.0)

## 🎯 1. 컴포넌트 개요 및 목표
**컴포넌트 이름:** `LossPotentialIndicator` (손실 위험 지표 위젯)
**목적:** 사용자가 데이터의 사소한 오류나 단절성(Data Fragmentation)을 발견했을 때, 이를 **단순한 경고가 아닌, 구체적인 금전적 손실($)**과 연결하여 인지하게 하는 것.
**핵심 원칙 (Anti-Loss Funnel):** 위기감 조성 $\to$ 문제 정량화 $\to$ 해결책 제시를 완벽히 따름.

## 🎨 2. 디자인 시스템 가이드라인 적용
*   **Primary Color:** Tech Blue (`#0066CC`) — 성공/정상 상태 CTA 및 강조색.
*   **Warning Color (Critical):** Warning Red (`#CC3333`) — 데이터 손실, 오류가 감지되는 모든 시각적 지점.
*   **Background:** Pure White (`#FFFFFF`).

## 🛠️ 3. 컴포넌트 상태별 상세 스펙

### A. 기본 상태 (Default State - Safe)
| 요소 | 설명/표시 값 | 디자인 명세 | 애니메이션/상호작용 |
| :--- | :--- | :--- | :--- |
| **Loss Counter** | $0.00 (손실액 없음) / Score: 98% | Deep Charcoal (`#1D1D1F`), 폰트 크기 최대. 스코어는 녹색 계열 사용 권장 (선택사항). | `Opacity: 1`, 부드러운 로딩 애니메이션(`transition: all 0.5s ease-out`). |
| **Indicator** | 작은 녹색 점 또는 체크 마크. | 미니멀하고 깔끔한 UI 요소로 배치. | 없음. 안정적인 느낌 부여. |

### B. 경고 상태 (Warning State - Potential Loss)
데이터의 연결성이 떨어지거나, 낮은 확률적 오류가 감지되었을 때 활성화됩니다.

*   **시각적 변화:** `LossCounter` 주변 영역 전체에 은은한 배경 오버레이(Overlay) 적용.
*   **컬러 변화:** 테두리 및 경고 텍스트에 Warning Red (`#CC3333`) 사용.
*   **카피라이팅 (필수):** "잠재적 손실 감지: 데이터 연결성 약화"와 같은 구체적인 문구 삽입.

### C. 오류 상태 (Critical Error State - High Loss Potential) **(핵심)**
개발팀이 가장 집중해야 할 부분입니다. API가 명백한 데이터 불일치 또는 시스템 단절을 보고할 때 트리거됩니다.

#### 1. 시각적 경고 애니메이션 (`Error Visualization`)
*   **트리거:** 페이지 로드 후, 혹은 특정 데이터 필드를 읽으려 할 때 즉시 발생.
*   **애니메이션:** 해당 컴포넌트 영역 전체가 **빨간색(`#CC3333`)의 강렬한 플래싱(Flashing)** 또는 'Glitch' 효과를 짧게 주어 시선 집중을 유도해야 합니다. (예: 0.5초 간격으로 Opacity 1 $\to$ 0.8 $\to$ 1 반복).
*   **경고 메시지:** 컴포넌트 상단에 `[⚠️ CRITICAL DATA ERROR]` 태그를 가장 크게 표시합니다.

#### 2. 인터랙션 상세 스펙 (Hover State & Popup) **(핵심)**
사용자가 경고가 발생한 특정 데이터 포인트 또는 위젯 위에 마우스를 올렸을 때 (`:hover`) 작동하는 구조입니다.

*   **A. Tooltip/Popup 활성화:** 일반적인 툴팁 대신, 배경과 분리된 **Semi-transparent Blur Glassmorphism Popover**를 사용합니다.
    *   `backdrop-filter: blur(10px);` (Apple Style 준수)
    *   팝업 배경색: Light Gray (`#F5F5F7`)에 미묘한 투명도 부여.
*   **B. 팝업 내부 구조:**
    1.  **헤드라인:** "🚨 데이터 손실 위험 발생" (Warning Red, Bold)
    2.  **문제 정의 (Problem):** "현재 API 응답값 $X$는 예상 스키마 $Y$와 불일치합니다." (구체적 오류 설명).
    3.  **손실 정량화 (Quantification):** **가장 중요한 부분.** 이 오류로 인해 발생할 수 있는 금전적 손실을 즉시 보여줍니다.
        *   `예상 최소 손실액: ₩1,200만 원 (최소 추정)` - 이 숫자는 크고 비비드하게 표시되어야 합니다. (`#CC3333`)
    4.  **해결책 제시 (CTA):** "데이터 무결성 진단 요청" 버튼을 다시 한번 강조합니다.

## ⌨️ 4. 개발자 컴포넌트 사용 가이드라인 요약
1.  **모든 손실액 계산:** 반드시 `(Time-Loss) + (Risk Cost)`의 합산 형태로 표시되어야 합니다. 단순한 단일 숫자 제시 금지. [근거: Self-RAG - 투명성 확보]
2.  **애니메이션 타이밍:** 경고 애니메이션은 '갑작스러움'이 중요합니다. Transition 시간은 짧게(0.1~0.3초) 가져가야 합니다.
3.  **CTA 버튼 문구:** "구매하기" 대신, **"손실 방지 계획 수립하기", "데이터 무결성 진단 신청"** 등 이득 기반의 구체적 행동 유도여야 합니다. [근거: Self-RAG - 카피라이팅 원칙]
